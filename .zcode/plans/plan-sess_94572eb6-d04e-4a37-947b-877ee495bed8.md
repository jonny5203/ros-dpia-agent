## Goal

Prove the RBAC mechanism works end-to-end: an authenticated user with the right global role gets 200, a user with the wrong role gets 403. No database, no migrations — just wire the existing `require_role()` to a test endpoint and write tests using the established `dependency_overrides` pattern.

## What exists already (no changes needed)

- `require_role(*allowed)` factory at `backend/app/api/deps.py:112-123` — raises 403 if `user.role not in allowed`. Currently dead code.
- `AppRole` enum at `backend/app/auth/models.py:12-23` — 5 roles: admin, privacy-officer, it-security, project-manager, viewer.
- Test pattern in `test_auth.py:107-154` — mocks `get_current_user` via `app.dependency_overrides` to inject a fake user without needing Keycloak.
- Routers mounted in `main.py:67-68` — health under `/api`, auth at root.

## Changes (3 files)

### 1. New file: `backend/app/api/v1/admin.py`
A minimal router with one protected endpoint to exercise `require_role`:

```python
# GET /api/v1/admin/whoami
# Requires AppRole.ADMIN — returns 403 for any other role.
# This is a test scaffold to prove the RBAC mechanism; real project-scoped
# routes land with the Phase 1 domain layer.
router = APIRouter(prefix="/v1/admin", tags=["admin"])

@router.get("/whoami")
async def whoami(user: CurrentUser = Depends(require_role(AppRole.ADMIN))) -> dict:
    return {"sub": user.sub, "role": user.role.value, "message": "admin access granted"}
```

### 2. Modified: `backend/app/main.py`
Mount the new router under `/api` (same prefix pattern as health):

```python
from app.api.v1 import admin, health
...
app.include_router(health.router, prefix="/api")
app.include_router(admin.router, prefix="/api")
```

### 3. New file: `backend/app/tests/test_rbac.py`
Tests covering the three RBAC outcomes, using the `dependency_overrides` pattern from `test_auth.py`:

- `test_admin_can_access_admin_endpoint` — mock admin user → 200
- `test_viewer_denied_admin_endpoint` — mock viewer user → 403
- `test_privacy_officer_denied_admin_endpoint` — mock privacy-officer → 403
- `test_unauthenticated_denied` — no mock (no session) → 401
- `test_require_role_allows_multiple_roles` — create a second endpoint allowing both admin AND privacy-officer → both get 200, viewer gets 403

Then test live in the browser/cluster:
1. Rebuild backend image (`make k8s-load`)
2. Restart api pod
3. Log in as `admin` / `password` → `curl -b cookie http://localhost:8081/api/v1/admin/whoami` → 200
4. Log in as `privacy.officer` / `password` → same curl → 403

## What this does NOT do

- No `project_members` table, no per-project RBAC, no 404-not-403 rule (that's Level 2 — the full Phase 1 domain layer with SQLAlchemy + Alembic)
- No database changes whatsoever
- The `/admin/whoami` endpoint is a test scaffold, not a real feature — it exists to prove the mechanism
